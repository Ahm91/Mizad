| قبول | سيناريوهات E2E يدوية/آلية (§6) | | رحلات المستخدم UC-xx |

### بيئة اختبارات التكامل
- سلسلة الاتصال: `MIZAD_TEST_SQL` وإلا `Server=.;Integrated Security=True;TrustServerCertificate=True`.
- `SqlServerFixture` (Collection Fixture): ينشئ `Mizad_IT_<guid>` بالترتيب `Arabic_100_CI_AI`، يطبق الترحيلات والبذور مرة لكل تشغيل، ويحذف القاعدة في النهاية.
- العزل بين الاختبارات: كل اختبار ينشئ بياناته بمعرفات فريدة (لا اعتماد على ترتيب)، أو يستخدم قاعدة مستقلة عند الحاجة (اختبارات الاستعادة والترحيل).
- إذا لم يتوفر SQL Server: الاختبارات **تفشل** برسالة واضحة (لا تُتخطى صامتة).

### أوامر التشغيل
```powershell
./scripts/build.ps1                                                   # restore + build Release + كل الاختبارات
./scripts/build.ps1 -UnitOnly                                         # وحدات فقط (لا يحتاج SQL Server)
dotnet test --solution Mizad.slnx -c Release                          # كل الاختبارات
dotnet test --project tests/Mizad.UnitTests
dotnet test --project tests/Mizad.IntegrationTests --filter-not-trait "Category=Performance"
dotnet test --project tests/Mizad.IntegrationTests --filter-trait "Category=Performance"
```
> المنصة: **Microsoft.Testing.Platform** (مفعّلة في `global.json` — D-003). الصيغة القديمة `dotnet test Mizad.slnx` و`--filter` الخاصة بـ VSTest لا تعمل. خيارات المرشحات أعلاه من xunit.v3 وتُتحقق عند إضافة أول اختبار أداء.

- `LoginViewModel`: الزر معطل أثناء الدخول؛ رسائل الأخطاء؛ لا تنفيذ مزدوج.
- `SalesPosViewModel`: مسح باركود يضيف/يزيد؛ تغيير الوحدة يعيد التسعير؛ الباقي للعميل؛ F9 مرة واحدة أثناء الانشغال؛ تفريغ بعد النجاح.
- `ReturnsViewModel`: Stepper لا يتجاوز المتاح؛ الملخص يتحدث؛ الزبون النقدي يفرض الرد النقدي.
- `NavigationService`: حارس التغييرات غير المحفوظة.
- `SidebarViewModel`: العناصر حسب الصلاحيات.
