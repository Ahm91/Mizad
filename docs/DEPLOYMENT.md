
## 2. أنماط التشغيل في الإنتاج

### 2.1 جهاز واحد
- SQL Server Express محلي (نسخة مسماة `MIZAD` أو الافتراضية الموجودة).
- مصادقة Windows. النسخ الاحتياطي إلى قرص محلي آخر أو خارجي (`D:\Mizad\Backup`).

### 2.2 شبكة محلية (خادم + عملاء)
```
[جهاز الخادم: SQL Server Express + مِيزاد (مضيف النسخ)] ── LAN ── [جهاز كاشير 1] [جهاز كاشير 2] [جهاز المدير]
```
- على الخادم: تفعيل TCP/IP في SQL Server Configuration Manager، منفذ ثابت 1433 (أو منفذ النسخة المسماة + خدمة SQL Browser)، قاعدة جدار حماية للمنفذ على الشبكة الخاصة فقط.
- **المصادقة:** في الشبكات بلا Domain تُستخدم مصادقة SQL بحساب تطبيق `mizad_app` عضو في `db_owner` **على قاعدة مِيزاد فقط** (لا sysadmin) — لازم للترحيل التلقائي والنسخ الاحتياطي (D-043، DATABASE_DESIGN §14.5). إنشاء القاعدة لأول مرة يتم في معالج الإعداد بحساب يملك `dbcreator` (أو مصادقة Windows لمدير جهاز الخادم)، والاستعادة بحساب إداري منفصل في شاشة الاستعادة فقط. كلمات المرور تُشفّر بـ DPAPI في `connection.json`.
- كل جهاز يحفظ إعداداته الخاصة في `machine.json` (الطابعات، المخزن الافتراضي، الصندوق الافتراضي).
- **مضيف النسخ:** جهاز الخادم فقط (`Backup.HostMachine`) لأن المسار يجب أن يكون على جهاز SQL Server.

### 2.3 المتطلبات الدنيا

## 3. التغليف والمثبت (Phase 18 — D-035)

1. **النشر:** `dotnet publish src/Mizad.Desktop -c Release -r win-x64 --self-contained true -p:PublishReadyToRun=true -o artifacts/publish` (مجلد، لا ملف واحد).
2. **المثبت (Inno Setup):** واجهة عربية؛ التثبيت في `C:\Program Files\Mizad`؛ اختصارات سطح المكتب وقائمة ابدأ؛ ملف إلغاء التثبيت.
   - **وضع خادم:** يكتشف SQL Server؛ إن لم يوجد يعرض تثبيت SQL Server Express (حزمة منفصلة أو تنزيل بإذن المستخدم) بنسخة `MIZAD`، تفعيل TCP/IP اختيارياً للشبكة، قاعدة جدار الحماية.
   - **وضع عميل:** يثبت البرنامج فقط.
   - لا يحذف عند إلغاء التثبيت: `%ProgramData%\Mizad`، مجلد النسخ، قاعدة البيانات.
3. **التوقيع:** توقيع `Mizad.exe` والمثبت بشهادة Code Signing (قرار المالك) لتجنب تحذير SmartScreen.
4. **الإصدار:** رقم واحد في `Directory.Build.props` (`<Version>`) يظهر في شاشة الدخول وقسم «الترخيص والنسخة» وسجل الأخطاء.

## 4. التشغيل الأول (D-044)
1. شاشة البداية ⇒ لا يوجد `connection.json` ⇒ **معالج الإعداد**: «هذا الجهاز هو الخادم» (اكتشاف نسخ SQL المحلية) أو «الاتصال بخادم في الشبكة»، ثم «اختبار الاتصال».
2. القاعدة غير موجودة ⇒ إنشاؤها (بصلاحية كافية) + الترحيلات + البذور تلقائياً؛ قاعدة موجودة ⇒ التحقق أنها قاعدة مِيزاد ثم الاتصال (وترقيتها تلقائياً إن لزم).
3. لا مستخدمين ⇒ معالج التهيئة: معلومات المحل ← العملة ومنازلها ← بيانات المدير وكلمة مروره.
4. على الأجهزة العميلة: إعداد الاتصال فقط ثم الدخول.

## 5. التحديث
1. تثبيت الإصدار الجديد فوق القديم (يُفضّل على الخادم أولاً، لكن أي جهاز بالإصدار الأحدث يستطيع الترقية).
2. عند الإقلاع تتولى شاشة البداية كل شيء **تلقائياً** (D-043): قفل الترحيل ⇒ نسخة `PreMigration` متحقق منها ⇒ تطبيق الترحيلات ⇒ مزامنة البذور ⇒ سجل تدقيق، مع عرض التقدم. الأجهزة الأخرى التي تُقلع في الأثناء تنتظر وتعرض «جارٍ تحديث قاعدة البيانات من جهاز آخر…». فشل النسخة يوقف الترحيل؛ فشل ترحيل يتراجع وحده ويبقي القاعدة سليمة.
3. الأجهزة العميلة بإصدار أقدم من مخطط القاعدة ترفض التشغيل برسالة «يرجى تحديث مِيزاد على هذا الجهاز إلى الإصدار X».
4. لا تحديث تلقائي عبر الإنترنت في 1.0.

## 6. النسخ الاحتياطي والاستعادة (تشغيلياً)
- اسم الملف: `Mizad_<Database>_<yyyyMMdd_HHmmss>_<Type>.bak`.
- **صلاحيات المسار:** حساب خدمة SQL (`NT Service\MSSQLSERVER` أو `NT Service\MSSQL$MIZAD`) يحتاج صلاحية كتابة على مجلد النسخ. البرنامج يختبر ذلك بنسخة اختبار ويعرض الخطوات عند الفشل.
- يُنصح بنسخة إضافية على وحدة تخزين خارجية (توصية ظاهرة في UI-12).
- الاستعادة: من شاشة الإعدادات فقط، بصلاحية `Backup.Restore`، مع إغلاق البرنامج على الأجهزة الأخرى (يُفصلون تلقائياً بـ `SINGLE_USER`)، ثم إعادة تشغيل البرنامج.
